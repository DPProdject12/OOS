🧠 Виртуальная память

Что это. Абстракция, при которой программа думает, что у неё есть непрерывный объём памяти, но ОС распределяет его по физическим страницам.

Как это работает

Процесс оперирует виртуальными адресами. Процессор через MMU переводит их в физические адреса в RAM.

Процесс → виртуальный адрес 0x0040A000 │ ▼ [ MMU + таблица страниц ] │ ▼ Физическая страница в RAM (или swap)
В геймдеве: на консолях виртуальное адресное пространство больше физической RAM. Движки резервируют большие виртуальные регионы под пулы ресурсов через VirtualAlloc.

💾 Swap и подкачка

Swap — область на диске, куда ОС выгружает редко используемые страницы.

УровеньВремя доступаОтносительно RAM
CPU L1~1 нс×100 быстрее
RAM~100 нс1×
SSD~100 мкс×1000 медленнее
HDD~10 мс×100000 медленнее
Важно: на HDD обращение к swap в 100 000 раз медленнее RAM. Активное использование swap = гарантированные фризы.

⚡ Page fault

Ситуация, когда процесс обращается к странице, которой нет в RAM. ОС загружает её с диска — это занимает время.

Процесс обращается к адресу → нет в RAM → PAGE FAULT → ОС читает с диска → страница в RAM → процесс продолжает
Правило: чем меньше page faults — тем лучше. В идеале — близко к нулю.

🌪️ Thrashing

Ситуация, когда ОС тратит больше времени на подкачку, чем на полезную работу.

  • Page faults растут лавинообразно
  • FPS падает до 5–10
  • Диск постоянно работает
В геймдеве: игрок бегает по открытому миру, RAM забита, ресурсы постоянно вытесняются. Решение — система стриминга с LOD и приоритетами.

🧩 Фрагментация памяти

Ситуация, когда свободной памяти достаточно, но она раздроблена на куски, и новый объект не влезает.

Внешняя и внутренняя

  • Внешняя: между занятыми блоками есть «дырки», но ни одна не подходит по размеру.
  • Внутренняя: объект занимает меньше, чем выделенная страница (потери).
В геймдеве: почему после 2 часов игры «память кончается», хотя реально занято меньше половины — память раздроблена.

📅 Планировщик процессов

Решает, какой процесс будет выполняться на CPU.

  • Round Robin: по очереди с квантом времени
  • Приоритетное: высокий приоритет — первым
  • Вытесняющее: ОС прерывает процесс
В геймдеве: рендер должен иметь высокий приоритет, фоновые задачи — низкий. SetThreadPriority в Windows.

🏁 Race Condition (гонка данных)

Ситуация, когда два процесса одновременно меняют одни данные — результат непредсказуем.

Ожидаем: counter = 200 Реально: counter = 156 (потеряно 44 операции!)

Решение — мьютекс

Мьютекс (mutex) — «замок», который пропускает только один процесс к данным. Остальные ждут.

В геймдеве: в многопоточных движках все общие данные защищают мьютексами. Классика — std::mutex в C++.

🔒 Deadlock (взаимоблокировка)

Два процесса держат ресурсы друг друга и ждут — оба навсегда зависли.

renderer: держит [RAM-A] ждёт [GPU-queue] audio: держит [GPU-queue] ждёт [RAM-A] 🔒 DEADLOCK! Оба процесса заблокированы.

Условия возникновения

  1. Взаимное исключение (ресурс держит один процесс)
  2. Ожидание с удержанием (держу A, жду B)
  3. Циклическое ожидание (A→B→A)
  4. Отсутствие принудительного освобождения

♻️ Object Pool (пул объектов)

Паттерн, при котором объекты создаются один раз и переиспользуются.

Без пула: new Bullet() → new Bullet() → new Bullet() (постоянные аллокации) → фрагментация, page faults, фризы С пулом: Bullet[] pool = new Bullet[1000] (один раз при старте) выстрел → берём из пула попадание → возвращаем в пул → никаких аллокаций в рантайме
В геймдеве: пули, частицы, враги, звуки — всегда через пул.

❓ FAQ

Почему FPS падает при свободной RAM?

Есть накладные расходы: page faults, переключения процессов, работа планировщика.

Может ли swap заменить RAM?

Нет. Swap — аварийный резерв. Работа только через swap в 100–1000 раз медленнее.

Зачем в консолях нет swap?

Фиксированная RAM для предсказуемости. Разработчики точно знают бюджет.

Что такое memory-mapped file?

Файл, видимый программе как область памяти. В играх так грузят большие ассеты.

Влияет ли размер страницы на производительность?

Да. Большие страницы уменьшают page faults, но увеличивают фрагментацию.
